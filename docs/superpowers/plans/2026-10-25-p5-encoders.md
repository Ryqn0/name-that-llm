# P5: Fine-Tuned Encoders — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fine-tune a transformer encoder as an 18-way classifier on Kaggle's GPUs. The
candidates are DeBERTa-v3-base and ModernBERT-base; the one that wins on CV goes on. Tune
its key hyperparameters with Optuna, blend it with the champion `lm_blend`, and submit the
blend as a leaderboard A/B test.

**Architecture:**
- **`encoder.py`** holds everything encoder-specific:
  - loading a model;
  - a hand-written PyTorch fine-tuning loop;
  - prediction;
  - the prompt-grouped CV loop, which can save each fold's model;
  - helpers that find and average the saved fold models offline.

  torch and transformers are imported lazily inside its functions (ADR 0002).
- **`tune.py`** gains an Optuna study for the encoder, with fold-level pruning.
- **`blend.py`** gains a weight search for any number of models.
- **`submit.py`** gains the three-model submission.
- **Notebooks:**
  - Three GPU research notebooks (select, tune, final), with internet on.
  - The offline submission notebook, which attaches the final notebook's output: the five
    fine-tuned fold models.

**Tech Stack:** the existing stack, plus:
- torch and transformers from Kaggle's GPU image. They are not package dependencies.
- Hugging Face Hub checkpoints `microsoft/deberta-v3-base` (MIT) and
  `answerdotai/ModernBERT-base` (Apache 2.0).
- Optuna, the existing `tune` extra.

**Spec:** `docs/superpowers/specs/2026-10-23-name-that-llm-design.md`. Relevant sections:
- §6.6: out-of-fold (OOF) predictions for every row; final decisions on 3 seeds × 5 folds
  plus the prompt bootstrap.
- §6.7 M4: fine-tuned encoders (DeBERTa-v3, ModernBERT) on Kaggle GPUs, with Optuna.
- §6.8: the offline batch submission, timed on 4,000 rows.
- §6.9: the A/B promotion gate.
- §8: PyTorch, Transformers, Optuna.
- §10, P5's exit criterion: *"An encoder model beats the baseline in CV."*
- §11: the risk of running out of GPU quota.
- Out of this plan: LLM fine-tuning with LoRA (M5) and calibrated ensembling (M6), both
  in P7; the app (P4), which comes next.

- **GPU:**
  - Push GPU notebooks with `kaggle kernels push -p <dir> --accelerator NvidiaTeslaT4` and

- **Mixed precision:**
  - On CUDA, training and inference run under `torch.autocast(dtype=torch.float16)`, with

  - On CPU (tests), everything stays float32.
- **Fixed epochs:** no per-fold early stopping. Choosing the epoch on the validation fold
  would leak it into the OOF score. The epoch count is a hyperparameter, tuned on seed-7
  folds.
- **Selection bias:**
  - Every choice is made on folds with **seed 7**: the model, the hyperparameters, the
    blend weights.
  - Final numbers are reported on seeds **42, 43 and 44**, plus the prompt bootstrap on
    seed 42.
  - Promote only if the CI lower bound is above 0, then only if the public LB beats
    **0.389**.
- **GPU training isn't bit-exact.** The same seed gives slightly different results from
  one run to the next. The bootstrap measures data noise, not this training noise, so
  treat a CI lower bound just above 0 with care.
- **Versions:**
  - The research notebooks (internet on) install the package pinned to an exact `main`
    commit.
  - The offline submission installs the wheel of tag **`v0.7.0`** (Task 7).
- **Printed results:** every number a decision depends on is `print()`ed, because the
  downloadable run log keeps only printed text (the P3b lesson).
- **W&B is optional.** The notebooks log only if the user has attached the `WANDB_API_KEY`
  Kaggle Secret, and nothing depends on it.
- **Submissions** are sent only in the foreground, right after the user's explicit go-ahead
  in that same turn. An unattended auto-submit gets blocked.

## Review Focus

1. **The classifier head's label order:** the probability columns must follow `LABELS`. A
   saved model with another order must be refused, never silently relabeled. Tests:
   `test_predict_proba_columns_follow_labels` and
   `test_predict_proba_refuses_another_label_order` (Task 1).
2. **Each fold trains a FRESH pretrained model:** weights carried over from a previous fold
   would leak its validation prompts into the next fold. Test:
   `test_fit_predict_fold_starts_fresh_each_time` (Task 1).
3. **A non-finite loss** (float16 overflow) must stop training with a clear error, rather
   than write garbage OOF probabilities. Test:
   `test_train_encoder_raises_on_non_finite_loss` (Task 1).
4. **Empty and very long passages** at inference: finite probabilities, and truncation at
   `max_length`. Test: `test_predict_proba_handles_empty_and_long_text` (Task 1).
5. **The offline fold models:** exactly `n_folds` models, in fold order, or a loud error
   that names the search root. Averaging four models silently is not acceptable. Tests:
   `test_find_fold_dirs_fails_loudly` and `test_saved_fold_models_round_trip` (Task 1).

```python
def make_tiny_encoder(texts, path, arch="deberta"):
    """A tiny RANDOM classifier (2 blocks, hidden 32) plus a word-level tokenizer built from
    `texts`, saved to `path`. Like real encoders, the tokenizer wraps each text in
    [CLS] ... [SEP], so even an empty text has 2 tokens."""
    torch = pytest.importorskip("torch")
    transformers = pytest.importorskip("transformers")
    from tokenizers import Tokenizer, models, pre_tokenizers, processors

    words = sorted({w for t in texts for w in re.findall(r"\w+|[^\w\s]", t)})
    vocab = ["[PAD]", "[UNK]", "[CLS]", "[SEP]", *words]
    word_level = Tokenizer(models.WordLevel({w: i for i, w in enumerate(vocab)}, unk_token="[UNK]"))
    word_level.pre_tokenizer = pre_tokenizers.Whitespace()
    word_level.post_processor = processors.TemplateProcessing(
        single="[CLS] $A [SEP]", special_tokens=[("[CLS]", 2), ("[SEP]", 3)]
    )
    tokenizer = transformers.PreTrainedTokenizerFast(
        tokenizer_object=word_level,
        pad_token="[PAD]",
        unk_token="[UNK]",
        cls_token="[CLS]",
        sep_token="[SEP]",
    )
    common = dict(
        vocab_size=len(vocab),
        hidden_size=32,
        num_hidden_layers=2,
        num_attention_heads=2,
        intermediate_size=64,
        max_position_embeddings=64,
        pad_token_id=0,
        num_labels=len(LABELS),
        id2label=dict(enumerate(LABELS)),
        label2id={label: i for i, label in enumerate(LABELS)},
    )
    if arch == "deberta":
        config = transformers.DebertaV2Config(**common)
    else:
        config = transformers.ModernBertConfig(
            **common, bos_token_id=2, eos_token_id=3, cls_token_id=2, sep_token_id=3
        )
    torch.manual_seed(0)
    transformers.AutoModelForSequenceClassification.from_config(config).save_pretrained(path)
    tokenizer.save_pretrained(path)
    return path
```

```python
device = next(model.parameters()).device
use_amp = device.type == "cuda"
labels = torch.tensor([LABELS.index(v) for v in y])  # an unknown label raises ValueError
total = cfg.epochs * math.ceil(len(texts) / cfg.batch_size)
warmup = int(cfg.warmup_ratio * total)
optimizer = torch.optim.AdamW(model.parameters(), lr=cfg.lr, weight_decay=cfg.weight_decay)
schedule = torch.optim.lr_scheduler.LambdaLR(  # linear warmup, then linear decay to 0
    optimizer,
    lambda s: s / max(1, warmup) if s < warmup else max(0.0, (total - s) / max(1, total - warmup)),
)
scaler = torch.amp.GradScaler(device.type, enabled=use_amp)
rng = np.random.default_rng(cfg.seed)
model.train()
for epoch in range(cfg.epochs):
    order = rng.permutation(len(texts))
    for start in range(0, len(texts), cfg.batch_size):
        idx = order[start : start + cfg.batch_size]
        enc = tokenizer(
            [texts[i] for i in idx],
            padding=True,
            truncation=True,
            max_length=cfg.max_length,
            return_tensors="pt",
        ).to(device)
        with torch.autocast(device.type, dtype=torch.float16, enabled=use_amp):
            loss = model(**enc, labels=labels[idx].to(device)).loss
        if not torch.isfinite(loss):
            raise FloatingPointError(
                f"non-finite loss at epoch {epoch}, batch {start // cfg.batch_size}"
            )
        scaler.scale(loss).backward()
        scaler.unscale_(optimizer)
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        scaler.step(optimizer)
        scaler.update()
        optimizer.zero_grad(set_to_none=True)
        schedule.step()
    # append this epoch's mean loss to the returned list
```

- [ ] **Step 3: Implement the study.**
  - **Warm start:** `study.enqueue_trial(...)` with the base config's three values, before
    `optimize`. It guarantees the result is no worse than the default on the tuning folds,
    which the P3b tuning lacked.
  - **The objective:**
    - Build the trial's config with `seed=seed` and record it as `user_attrs["config"]`
      *before* training, so pruned trials keep it too.
    - Then, for each fold `k` in `tune_folds`: run `fit_predict_fold` and compute the
      fold's balanced accuracy.
    - Report the running mean as step `i`, and raise `optuna.TrialPruned` when
      `trial.should_prune()`.
    - Return the mean.
  - **Sampler:** `TPESampler(seed=seed)`.
  - **Pruner:** `MedianPruner(n_startup_trials=3)`. It prunes at the fold level: after
    fold 0, a trial below the median of earlier trials on that same fold skips fold 1.
    That halves the cost of bad trials, and unlike per-epoch pruning, it never compares
    learning-rate schedules midway.
  - **Docstring:** explain the warm start and fold-level pruning, and why fixed epochs
    rather than early stopping.
