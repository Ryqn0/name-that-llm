# P4: the live demo app (App v1 and CD) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public Hugging Face Space where a pasted passage gets the champion's ranking of the
18 models in about 5 seconds, redeployed automatically on every merge.

**Architecture:**
- **Inference lives in the package:** `champion.py` flattens the text, runs `lr`, a 10-block
  Qwen LM head and the 5 encoder folds, then blends.
- **Packaging:** the champion becomes an MLflow `pyfunc` (`registry.py`), registered on DagsHub
  by `scripts/register_champion.py`.
- **Serving:** a FastAPI app (`api.py`, `serve.py`, one static page) runs in one Docker image
  on a free Space.
- **Deployment:** `deploy-app.yml` runs `scripts/deploy_space.py`.

**Tech Stack:** Python 3.13, FastAPI, Uvicorn, MLflow (DagsHub), PyTorch 2.11.0 (CPU),
transformers 5.16.1, scikit-learn, Docker, Hugging Face Spaces, `huggingface_hub`, GitHub
Actions.

**Spec:** [docs/superpowers/specs/2026-10-26-p4-app-design.md](../specs/2026-10-26-p4-app-design.md),
which builds on [the project design](../specs/2026-10-23-name-that-llm-design.md) §6.11, §7
and §8.

## Global Constraints

- **Free tiers only:** a Hugging Face Space on CPU basic (2 vCPUs, 16 GB) and DagsHub's free
  MLflow. No GPU, no billing.
- **The champion exactly as submitted:**
  - `configs/ensemble.yaml`, weights 0.70 / 0.15 / 0.15;
  - its blend `lm_blend`: `4b-base`, layer 6, window 4, max_length 512, C 0.1;
  - its text model `lr`;
  - the 5 seed-42 encoder fold models, max_length 512.
- **Qwen:** `Qwen/Qwen3-4B-Base` at a pinned revision, first **10** blocks (never 9), float32,
  CPU.
- **Serving:** `torch.set_num_threads(2)`; one prediction at a time; at most 4 requests waiting,
  beyond that 503.
- **Input limits:**
  - 20 to 1,000 words, counted after flattening, both ends included; otherwise 422.
  - A request body of at most 32,000 bytes; otherwise 413.
  - 10 requests per minute per visitor; otherwise 429.
- **Privacy and rules:**
  - Never store or log a visitor's text.
  - No competition passage ever appears in the app, the repo, the Docker image, the logs or
    the tests.
- **Versions in the image:** torch 2.11.0 (the CPU build) and transformers 5.16.1, Kaggle's
  versions. They stay out of the package's dependencies (ADR 0002).
- **Secrets** live only in GitHub Secrets and Space secrets: `HF_TOKEN`, `DAGSHUB_TOKEN`.
- **The registry:** registered model `name-that-llm`, alias `champion`, in a private DagsHub
  repo.
- **Display text:**
  - Company names: Anthropic, Google, Z.ai, OpenAI, Moonshot, Qwen.
  - "How sure?" labels: "Fairly sure", "Unsure", "Very unsure".
- **Conventions:**
  - test first, fake data in tests, heavy "why" comments;
  - one branch, PR and CI-gated merge per task;
  - the ledger, then the journal (`docs/journal/p4-app.md`) at the end;
  - package version 0.8.0.
- **Approvals:** the first registration and the first deploy each need the user's explicit OK,
  given in the session.

## Review Focus

1. **Text in unusual shapes:** emoji, Chinese or Japanese characters, one 5,000-character URL,
   punctuation only. The visitor gets a valid ranking or a clear 422, never a 500. Tests:
   `test_predict_proba_handles_unusual_text` (Task 3) and
   `test_predict_rejects_text_without_words` (Task 5).
2. **The word limits at their edges:** exactly 20 and 1,000 words are accepted. 19 and 1,001
   are rejected with a message that gives the counted number. Whitespace alone gets a 422.
   Test: `test_word_limits_are_inclusive` (Task 5).
3. **A burst of visitors:** past the 4 waiting, requests get a 503 "busy, try again in a
   moment", and every request in line is still answered. Test:
   `test_single_flight_turns_away_beyond_the_line` (Task 5).
4. **Before the model loads, or after loading failed:** `/predict` returns a 503 with a plain
   message; `/health` returns 503 while loading and 500 after a failure. Never a traceback.
   Test: `test_health_and_predict_while_loading_and_after_failure` (Task 5).
5. **The version shown is the version loaded:** after the `champion` alias moves, a running
   app keeps answering with the version it loaded and says so, while a newly loaded app
   reports the new one. Test: `test_load_registered_pins_the_alias_version` (Task 4).

### Task 1: Flatten pasted text like the training data

**Files:**
- Modify: `src/name_that_llm/data.py` (add `flatten_text`, export it in `__all__`)
- Test: `tests/test_data.py`

**Interfaces:**
- Produces: `flatten_text(text: str) -> str`. Markdown becomes one paragraph with single
  spaces, then goes through `normalize_text`.

**The rules, decided from the training data:**
- No passage has a line break, a heading, `**`, a backtick, a list bullet or a list
  numbering, so the host stripped those.
- 14 passages keep `*word*`-style asterisks, so single `*` survive.
- The 11 "number + dot" cases are ordinary text (3 are years), and they survive.

Concretely:
- **At the start of a line**, remove: headings (`#` to `######` plus a space), quotes (`> `),
  bullets (`- `, `* `, `+ `), numbering (`1. `, `2) `), code-fence lines (```` ``` ````,
  with or without a language), and table separator lines (`|---|`).
- **Everywhere**, remove: `**` and `__`, backticks, and the pipes of table rows.
- **Links:** `[text](url)` becomes `text`, and `![alt](url)` becomes `alt`.
- **Finally:** every run of whitespace becomes one space, then `normalize_text`.

def test_load_lm_layers_matches_the_full_model_on_kept_layers(tiny_qwen, fake_train):
    texts = fake_train["text"].tolist()[:5]
    full, tokenizer = load_lm(tiny_qwen, device="cpu")

    a = pooled_hidden_states(texts, full, tokenizer, layers=range(6, 10), batch_size=2)

def test_load_lm_layers_with_nine_blocks_changes_layer_nine(tiny_qwen, fake_train):
    # The trap: the LAST hidden state is passed through the final normalization, so a
    # 9-block cut no longer returns the plain output of block 9.

    a = pooled_hidden_states(texts, full, tokenizer, layers=[9], batch_size=2)
    b = pooled_hidden_states(texts, cut9, tokenizer, layers=[9], batch_size=2)
    assert np.abs(a - b).max() > 1e-3

**Files:**

- Modify: `.github/workflows/ci.yml` (the `torch` job also runs `tests/test_champion.py`)

**Interfaces:**
- Consumes:
  - `flatten_text` (Task 1) and `load_lm_layers` (Task 2);
  - `submit._aligned_proba`, `lm.pooled_hidden_states`, `lm.select_layers`,
    `encoder.predict_proba`, `blend.blend` and `labels.LABELS`.
- Produces:
  - `Band(label: str, min_top: float, accuracy: float)`, a frozen dataclass.
  - `fit_confidence_bands(proba: np.ndarray, y: np.ndarray) -> list[Band]`:
    - three bands, cut at the terciles of the top probability, highest first, labelled
      "Fairly sure", "Unsure", "Very unsure";
    - the lowest band has `min_top = 0.0`;
    - `accuracy` is the share of rows in the band whose top label equals `y`.
  - `describe_confidence(top: float, bands: Sequence[Band]) -> Band`: the first band with
    `min_top <= top`.
  - `Champion`, a dataclass:
    - fields: `text_model`, `lm_head`, `lm_train_mean: np.ndarray`, `lm: tuple` (model,
      tokenizer), `encoders: list[tuple]` (model, tokenizer, in fold order),
      `weights: tuple[float, float, float]`, `lm_layer: int = 6`, `lm_window: int = 4`,
      `lm_max_length: int = 512`, `encoder_max_length: int = 512`;
    - method `predict_proba(texts: Sequence[str]) -> np.ndarray`: shape (n, 18), columns in
      `LABELS` order.
    - **The steps:**
      1. Flatten the texts.
      2. `lr`.
      3. LM features (the mean of layers 6–9). Non-finite rows become `lm_train_mean`;
         then the LM head.
      4. The mean of the encoders. Non-finite rows become uniform (1/18).
      5. `blend` with `weights`.

  - `load_registered(name: str = "name-that-llm", alias: str = "champion") ->
    tuple[Predictor, dict]`:
    - it resolves the alias to a version **once**, then loads `models:/{name}/{version}`;
    - the predictor has `predict_proba(texts) -> np.ndarray` and an `info` dict:
      `{"model_name", "model_version", "alias", "encoder_folds", "qwen_revision", "bands"}`,
      where `bands` is a `list[Band]` rebuilt from `meta.json`.

### Task 5: The web API and the page

**Files:**
- Create: `src/name_that_llm/api.py`, `src/name_that_llm/serve.py`,
  `src/name_that_llm/static/index.html`
- Test: `tests/test_api.py`
- Modify: `pyproject.toml` (the `serve` extra adds `fastapi>=0.115`, `uvicorn[standard]>=0.30`,
  `httpx>=0.27` and `huggingface_hub>=0.34`), `uv.lock`, `.gitignore`
  (`src/name_that_llm/BUILD_COMMIT`)

**Interfaces:**
- Consumes: `flatten_text`, `describe_confidence`, `Band`, `LABELS` and `LAB_OF`;
  `registry.load_registered` (in `serve.py` only).
- Produces:
  - `Predictor`, a Protocol: `predict_proba(texts: Sequence[str]) -> np.ndarray` and
    `info: dict` (Task 4's keys).
  - `LAB_NAMES: dict[str, str]`: `{"anthropic": "Anthropic", "google": "Google", "zai": "Z.ai",
    "openai": "OpenAI", "moonshot": "Moonshot", "qwen": "Qwen"}`.
  - `SingleFlight(max_waiting: int)`, an async context manager. It raises `Busy` when
    `max_waiting` requests are already in line.
  - `RateLimiter(per_minute: int, clock: Callable[[], float] = time.monotonic)` with
    `allow(key: str) -> bool`, over a sliding 60-second window.
  - `build_commit() -> str`: reads the package file `BUILD_COMMIT`, else the `GIT_COMMIT`
    environment variable, else `"unknown"`.
  - `create_app(load_predictor: Callable[[], Predictor], *, max_waiting: int = 4,
    per_minute: int = 10, max_body_bytes: int = 32_000) -> FastAPI`. At startup, the
    predictor loads in a background thread.
  - **The routes:**
    - `GET /`: the page.
    - `GET /health`: 200 `{"status": "ok"}`; 503 `{"status": "loading"}`; 500
      `{"status": "failed", "error": ...}`.
    - `GET /version`: `{"package", "commit", "space_id"}`, plus the predictor's `info` once
      it has loaded. `space_id` comes from the `SPACE_ID` environment variable that HF sets.
    - `POST /predict` takes `{"text": str}` and returns:
      - `"ranking"`: all 18 entries `{"model", "lab", "probability"}`, sorted highest first;
      - `"confidence"`: `{"label", "right_in_10"}`, where `right_in_10` is
        `round(accuracy * 10)`;
      - `"model_version"`, `"encoder_folds"`, and `"seconds"` (one decimal).
    - The visitor key is the first entry of `X-Forwarded-For`, else the client's address.
  - `serve.py`: `app = create_app(_load)`. `_load` sets `torch.set_num_threads(TORCH_THREADS,
    default 2)`, then calls `load_registered(MODEL_NAME, MODEL_ALIAS)`.
  - **The page** follows the design §3 and the mockup:
    - the form, with the hint "works best on 50 to 300 words";
    - a progress message, the best guess, the "How sure?" line, the top 5, "Show all 18",
      and the warning box (its 4 points);
    - plain messages for 413, 422, 429 and 503;
    - a footer from `/version`, and a model card link to
